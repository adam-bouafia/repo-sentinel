### [medium] Workflows pin actions/checkout@v4 and actions/upload-artifact@v4, which run on the removed node20 runtime
*ci* - open since 2026-09-25

.github/workflows/ci.yml uses `actions/checkout@v4` (line: `- uses: actions/checkout@v4`) and `actions/upload-artifact@v4`; .github/workflows/release.yml also uses `actions/checkout@v4` in the `publish` job. Both v4 majors declare `runs.using: node20`. GitHub's changelog "Deprecation of Node 20 on GitHub Actions runners" states runners defaulted to Node 24 from 2026-06-16 and that Node 20 is removed from the runner on 2026-09-23 — a date that has already passed. The latest run of each workflow (CI run 36126362129 and Release run 36126363686, both 2026-09-25) still succeeded, so the removal has evidently not reached these runners yet, but these pins can start failing without warning and would block the tag-triggered Release job that publishes to extensions.gnome.org. Latest upstream for both actions is v7.0.1 (actions/checkout v7.0.1 published 2026-07-20, actions/upload-artifact v7.0.1 published 2026-04-10). Note the upgrade crosses three majors (v4→v5→v6→v7); only v5 is the Node 24 runtime move, so the bump should be reviewed rather than applied blind.

Evidence: ci.yml: `- uses: actions/checkout@v4` and `- uses: actions/upload-artifact@v4`; release.yml: `- uses: actions/checkout@v4`. upstream_version(github, actions/checkout) = v7.0.1 (2026-07-20); upstream_version(github, actions/upload-artifact) = v7.0.1 (2026-04-10). https://github.blog/changelog/2025-09-19-deprecation-of-node-20-on-github-actions-runners/ (Node 20 removed from runners 2026-09-23).

Fix: Bump both workflows to actions/checkout@v7 and actions/upload-artifact@v7 and re-run CI on master before tagging the next release; check the v5/v6/v7 release notes for behaviour changes (upload-artifact v5+ changed default artifact handling).

### [low] Preferences allow a 1-second update interval that the extension silently clamps to 2
*other* - open since 2026-09-25

prefs.js builds the Update Interval SpinRow with `new Gtk.Adjustment({ lower: 1, upper: 60, ... })`, but extension.js `_scheduleNext()` schedules with `const interval = Math.max(2, this._settings.get_int('update-interval'))`. Worse, `_updateData()` reads the unclamped value for the energy conversion (`const interval = this._settings.get_int('update-interval'); ... const energyKWh = (power.watts * interval / 3600) / 1000;`), so a user who sets 1 second gets samples taken every 2 seconds but energy integrated over 1 second — roughly half the true emissions, with no warning. The gschema default is 5 and its description gives no minimum.

Evidence: prefs.js: `adjustment: new Gtk.Adjustment({ lower: 1, upper: 60, ... })` for 'Update Interval'; extension.js `_scheduleNext()`: `const interval = Math.max(2, this._settings.get_int('update-interval'));`; extension.js `_updateData()`: `const interval = this._settings.get_int('update-interval');` then `const energyKWh = (power.watts * interval / 3600) / 1000;`.

Fix: Set the SpinRow adjustment `lower: 2`, and use the same clamped interval value in `_updateData()` for the energy calculation so the timer period and the integration window always agree.

### [info] Bundled country carbon-intensity dataset has no documented source or vintage
*docs* - open since 2026-09-25

data/country_intensity.json is a flat map of 57 ISO country codes to gCO2/kWh values (e.g. "FR": 60, "PL": 700, "ZA": 800) with no source, methodology or year field, and lib/carbon.js merges it over a hard-coded COUNTRY_INTENSITY_BUILTIN table with the same style of values. The README only says "ElectricityMaps and open data projects for providing intensity references" under Acknowledgments. Grid intensities move by tens of g/kWh per year, so users of the default 'auto-country' provider (gschema default `intensity-provider = 'auto-country'`) cannot tell how stale the numbers are.

Evidence: data/country_intensity.json: `{ "US": 388, "CA": 150, "MX": 430, ... "TW": 500 }` — no metadata keys. lib/carbon.js: `const COUNTRY_INTENSITY_BUILTIN = { 'US': 388, 'CA': 150, ... }` and `loadCountryIntensityMap()` merges the JSON over it. schema default: `<key name="intensity-provider" type="s"><default>'auto-country'</default>`.

Fix: Add a `_source` / `_year` comment block or sidecar note (e.g. Ember or ElectricityMaps yearly averages, with the data year) and mention the vintage in the README provider notes.
